# 要件定義 v1

## ターゲット
- 研究室で輪講を実施している人
- 教科書・参考書を使って輪講形式で学習しているグループ

## 現状の課題
1. 輪講がどこまで進んだか曖昧
2. 進度の目安・目標が立っていない
3. 学んでいることの全体像が掴めていない
4. 学ぶことの目的意識が薄い
5. 問題演習が多く、全員が理解できているか分からない
6. 新しい概念が次々出てきて復習が追いつかない
7. 担当者の予習量に見合う進度が得られていない

## 解決の方針
- 進度が一覧でパッと見えるようにする（1, 2, 3）
- 進度の目標を立てられるようにする（2）
- 演習の実施記録を残す（5, 6）
- 担当者が準備しやすい仕組みを作る（7）
- 後から全員が振り返れるようにする（3, 6）

---

## MVP機能（最初に作るもの）

| # | 機能 | 解決する課題 |
|---|---|---|
| 1 | 輪講を作成し、教材の章/回リストを登録できる | 3（全体像） |
| 2 | 各回に担当者・予定日を割り当てられる | 7（担当準備） |
| 3 | 各回のステータス（未着手/進行中/完了）を更新し、進捗が一覧でパッと見える | 1, 3（進捗の曖昧さ） |
| 4 | 全体の目標ペース（例: 週1回、◯月末までに完了）を設定し、実進捗との差分が見える | 2（目安がない） |
| 5 | 各回に演習の実施メモ・振り返りメモを残せる | 5, 6, 3（振り返り） |
| 6 | 各回に「この回で学ぶこと」を一言書ける欄 | 4（目的意識） |

### MVPに含めない（Phase 3以降で検討）
- 演習の理解度を個人ごとに詳細集計する機能
- 復習リマインド・スケジューリング機能（間隔反復など）
- 通知・チャット連携

---

## データモデル（軽量オブジェクト定義）

```
Seminar（輪講）
- id
- name              例: "パターン認識輪講"
- material_title    教材名
- target_pace       例: "週1回" / 目標終了日
- members: [Member]

Member（参加者）
- id
- name

Unit（回・章）
- id
- seminar_id
- order             第何回・第何章か
- title             章タイトル
- objective         この回で学ぶこと（一言）
- presenter_id      -> Member
- planned_date
- status             not_started | in_progress | done
- notes             演習・振り返りメモ（自由記述）
- needs_review       要復習フラグ (bool)
```

`Exercise`（演習単体オブジェクト）はMVPでは作らず、`Unit.notes` に自由記述で残す形にして複雑さを抑える。演習を個別管理したくなったら Phase 2 以降で切り出す。

---

## 画面（ラフ、3枚构成）
1. **輪講一覧**: 参加中の輪講カード（進捗% + 直近の回）
2. **輪講詳細（進捗ビュー）**: Unitを縦に並べ、ステータス色分け + 目標ペースとの差分表示
3. **回の詳細**: 担当者・予定日・objective・notes の編集
